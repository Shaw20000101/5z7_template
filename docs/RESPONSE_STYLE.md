# 回复约定：先简答，再展开

默认先用1–3句话写结论、交付链接和关键限制。过程、实现、验证明细放在下面的折叠区。失败、阻塞、尚未验证及需要用户决定的事项必须在简答中明确，不能隐藏。

在支持HTML折叠的界面或GitHub Markdown中使用：

```markdown
已完成所需功能，相关检查通过。文件与使用方式见交付链接。

<details>
<summary>展开查看改动与验证</summary>

- 改了什么、为什么改。
- 实际运行了哪些检查，结果是什么。
- 尚未覆盖的范围与已知限制。
- 必要的来源、报告和复现入口。

</details>
```

功能达到预期但尚无提交授权时，在简答后、折叠区之外询问：

“按你的版本保存约定，需要将本次代码和文档保存为一个本地Git提交吗？”

询问不阻止文件交付，不自动授权提交或推送。已有对应授权时直接在授权范围内完成。

GitHub支持`details/summary`；聊天客户端由其渲染能力决定。若不支持折叠，使用简答和详细文档链接，不声称已实现可点击展开，也不为此额外发布网站。
