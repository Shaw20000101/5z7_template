# 任务与运行记录规范

## 记录什么

日常代码工作用TASKMEMORY和必要报告记录；实际实验、复评或展示再登记相应身份，不把文档编辑伪装成实验。

执行前明确唯一编号、输入清单、实际代码（提交号及未提交改动/快照哈希）、有效配置、环境、依赖或权重、种子、预算、验收口径及独立输出目录。缺失写未知，不适用写明原因。

每次尝试单独保存实际命令参数、工作目录、必要环境覆盖（不含密钥）、UTC起止时间、阶段、退出码和日志。执行命令与计划命令分开；预计数量、实际数量及缺失分开。

状态使用 `planned`、`running`、`completed`、`failed`、`interrupted`、`paused`。`paused`仅表示用户要求暂停。完成必须有收据和必要验证；退出码0不自动说明实验效果达标。

## 本地运行目录

每次使用新的 `generated_artifacts/<task-id>/<attempt-id>/`。建议保存plan、execution、progress、logs、outputs、validation和receipt，按实际任务需要设置，不为凑文件伪造内容。

计时写明测量边界和实际处理数量，区分核心计算、启动/加载、序列化、评测与渲染；估算另列，未知终点不补推。失败、中断、拒绝和部分输出保留，恢复说明复用了什么、实际新增执行了什么。

本地运行目录不进入Git。可复制 [计划](templates/PLAN.json)、[执行](templates/EXECUTION.json)、[收据](templates/RECEIPT.json) 骨架并填入实际值。

## 可进入Git的轻量记录

在 `docs/provenance/<task-id>/` 保留必要的精简输入清单、代码/配置身份、证据哈希和外部取回方式，不复制数据、模型、完整日志、逐样本结果或密钥。

登记位于 [registry](registry/README.md)。ID在四张表中全局唯一，稳定标识实际对象；不以可变的latest别名或端口代替身份。新生成、重新评测和展示分别关联，不把旧结果重新命名为新执行。

证据条目采用相对**项目根目录**的路径与实际SHA256；已登记证据改变时先查明原因，必要时新建版本和说明，不能为消除检查错误直接刷新预期哈希。

大型或外部证据使用external_evidence记录URI、哈希和访问说明。自检不访问外部存储；没有取得证据时明确写未核验。公开前检查轻量记录是否暴露凭证、个人路径或内部地址。

## 交付维护

专题报告说明问题、最终变化、实际验证、结果、限制与复现入口。从reports/README和docs/README建立索引；关键入口变化更新PROJECT_MAP，任务状态更新TASKMEMORY，跨任务决定更新PROJECT_MEMORY。

修改登记后运行 `python3 scripts/validate_records.py`。结构、链接和SHA检查只说明记录一致，不代替功能测试、实验复评或浏览器验证。效果达到预期后，按照Git约定询问是否保存本地版本。
