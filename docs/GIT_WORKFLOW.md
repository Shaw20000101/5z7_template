# Git版本保存与数据边界

## 什么时候主动询问

功能已经完成、相关检查通过且达到预期时，先把报告、索引和任务记忆维护完，再询问是否保存一个本地Git提交。不要在工作还未做完时让用户批准一个空泛的计划。

询问示例：“功能已完成并通过相关检查。是否需要把本次代码和文档保存为一个本地Git提交？”

用户已经明确授权对应提交时无需重复询问；提交授权不自动包含远端推送。未验证的效果要标明待验收，不能以“稳定版本”名义保存。

## 可以进入Git

- 本次相关的代码、文档与可公开配置示例。
- 复现步骤、来源编号、哈希和精简清单。
- 功能或实验结论报告中的必要汇总，不嵌入原始样本或大批逐样本明细。

## 不进入Git

原始数据集、权重与检查点、候选数组、逐样本结果、完整日志、缓存、生成图片和视频、结果压缩包及凭证。不通过Git LFS提交实验数据。CSV、JSON等文本格式也可能是实验数据，不能仅凭扩展名认定可提交。

这些文件保存在本地运行目录或用户明确指定的外部存储；Git中的报告只记录足够的来源和取回方式。

## 授权后的保存步骤

1. 查看工作区状态，确认已有修改和本次修改的边界。
2. 显式列出要暂存的文件，不使用未经审查的批量暂存。
3. 审查暂存差异、文件数量与体积，确认没有数据、凭证或无关改动。
4. 运行必要检查，使用准确的提交说明保存，并告知用户提交编号及未包含内容。
5. 只有得到推送授权才推送；创建仓库、设置远端、强制推送或重写历史也不从本地提交授权中推断。

如果仓库尚未初始化，先说明准备初始化的确切目录，在获得相应授权后执行，不能误在上级项目或嵌套目录创建仓库。

`.gitignore`只影响尚未被跟踪的文件。发现已经跟踪的数据时，说明范围并提出清理方案，不自动删除数据或改写历史。

## 上传此模板到GitHub

上传本模板目录的内容作为仓库根目录，保留隐藏的`.gitignore`。模板没有预置Git历史、远端地址或个人环境路径；不需要携带上层项目。先执行 [维护结构自检](REPRODUCTION.md)，再按用户授权执行Git操作。
